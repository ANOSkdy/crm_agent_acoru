# DeepSeek 案件アシスタント

> 2026-09-20: UIと参照範囲を[独立したAcoru AI](WORKSPACE_AI.md)へ更新。この文書は初期の案件別実装とDB更新機構の記録。現在の入口は `/assistant`。

2026-09-19 実装。案件詳細の「進捗と、次の一手を相談する」から利用する。

## できること

- 同じ案件の活動・タスク・現在の方針を参照しながら日本語で相談する。
- 進捗、方針・採用理由、商談情報、活動追加、タスク追加・完了の更新案を作る。
- 変更前の値と比較し、内容を編集してから反映する。不要な案は却下する。
- 再読み込み後も会話・更新案・採用した方針を確認する。

初期版は1案件につき1つの社内共有会話。管理者は全案件、memberは担当案件の更新案を反映できる。viewerは相談と閲覧のみ。既存の担当者未設定案件は管理者が更新できる。

## 構成案からの変更

利用者指定に合わせ、AI実行先をDeepSeekへ変更。アプリ内の上限付きツール呼び出しループとNeon保存を使う。OpenAI Agents API、MCP公開、外部ワーカーは利用しない。

既存の顧客要約・次アクション生成も同じDeepSeek接続を使う。AIルートに認証と送信元検証を追加し、案件を指定した次アクション生成ではその案件の活動だけを使用する。

## ローカルで使う

`C:\dev\crm_agent` で `pnpm dev` を実行し、ターミナルに表示されたURL（通常 `http://localhost:3000`）を開く。開発サーバーは同じディレクトリで1つだけ起動する。終了するときは起動したターミナルで `Ctrl+C` を押す。

案件の進捗更新・方針相談は「案件」から対象案件の詳細を開いて利用する。顧客の要約は顧客詳細の「顧客サマリー生成」を押す。生成中はボタンを無効にし、完了すると同じ画面のサマリー一覧を更新する。失敗時は画面内にエラーを表示する。`/api/ai/summarize-company` は画面から呼び出すPOST APIのため、ブラウザーで直接開くURLではない。

## 環境変数

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | 既存のNeon接続 |
| `DEEPSEEK_API_KEY` | サーバー専用APIキー |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com`（公式ホストのみ許可） |
| `DEEPSEEK_MODEL` | 利用モデル。既定値 `deepseek-flash` |

`node scripts/setup-deepseek.mjs <credential-file>` で指定ファイルからDeepSeek設定だけを `.env.local` に取り込める。`DEEPSEEK_FAST_MODEL` を `DEEPSEEK_MODEL` に割り当てる。キーの値は出力しない。`.env.local` はGit管理対象外。

ローカルの環境変数はVercelには自動反映されない。公開時にはVercelの対象環境へ上記変数を設定し、アプリをデプロイする。今回の作業ではローカル設定と接続先DBの更新を実施し、本番アプリのデプロイは実施していない。

## DB

`pnpm db:migrate` で順序付きマイグレーションを適用する。`schema_migrations` にファイル名とチェックサムを保存し、適用済みファイルの書き換えを拒否する。新規の変更は別ファイルで追加する。

追加テーブル: `deal_contexts`、`deal_decisions`、`agent_threads`、`agent_runs`、`agent_messages`、`agent_change_requests`。既存認証スキーマの再現用マイグレーションも追加。

`deals.agent_revision` とトリガーで、手動編集を含む案件・活動・タスク・進捗・方針の変更を検出する。更新案の版と一致しなければ409を返す。`apply_agent_changes` は案件ロック、現在の権限確認、全操作、反映済み化、監査記録を1トランザクションで行う。同じ更新案の二重適用は既存結果を返す。

## 実行と障害時の扱い

1時間に利用者あたり30回、1案件につき同時実行1件、最大5回のモデル応答、各応答60秒・全体140秒を上限にする。Next.jsルートの最大実行時間は180秒。

入力は送信前に保存され、ブラウザーを閉じても保存済み内容を再取得できる。ただし実行基盤はリクエストに結びつくため、プロセス終了後にAI処理を自動再開する機能はない。3分以上残った実行を失敗として表示し、利用者が再送する。反映前の案は実データを変更しない。API・DB障害の詳細や接続情報は画面・ログへ出力しない。

モデルには直近40メッセージ、活動30件、未完了を優先したタスク100件、採用方針20件を渡せる。ツール結果は1回40,000文字まで。画面の会話は直近100メッセージ。長期間の会話要約・過去メッセージのページ送り、ファイル本文検索、定期実行、案件横断分析は今後の拡張。

## 検証

```text
pnpm test:agent
pnpm test:agent:db
pnpm typecheck
pnpm lint
pnpm build
```

DBテストは同一トランザクション内の一時スキーマでマイグレーション、権限、原子的適用、重複防止、競合、別案件拒否、ロールバックを確認し、終了時に除去する。

`scripts/test-fixture.ts` は一時案件・一時ユーザー・セッションを用意し、IDをGit管理外の `.local-test/fixture.json` に保存する。ブラウザー/API検証後は `pnpm exec tsx scripts/test-fixture.ts cleanup` で、そのIDのレコードのみを削除する。本番の既存案件で書き込みテストをしない。

ブラウザー検証ではDeepSeekの実応答、確認前に業務データが変わらないこと、カードの編集、反映、再読込後の保存、再送時の重複防止を確認した。方針と理由の保存後、後続相談が保存内容を参照し、相談のみでは変更案が増えないことも確認した。APIテストでは未認証・不正な送信元・viewerの更新・不正入力を拒否することを確認した。

回答と更新案は `finish_response` の構造化出力として一緒に検証・保存する。モデルのテキストだけで「更新案を作った」と扱わない。

顧客サマリーは、一時顧客でボタン操作からDeepSeek実応答、APIの200応答、画面内の結果表示、再読み込み後の保存を確認した。検証用レコードとサーバーは終了時に削除・停止した。

DeepSeekの実装仕様は[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)と[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)を参照。
