# ユーザー別1Password OTP

既存のID・パスワードに加え、ユーザー別TOTPを必須にする。ShareBoxと同じRFC 6238 / SHA-1 / 6桁 / 30秒 / 前後1ステップ。1Password APIは使わず、1Passwordの「ワンタイムパスワード」欄で生成したコードを照合する。

## 初回登録とログイン

1. CRMに既存IDとパスワードを入力する。この段階ではCRMデータにアクセスできない。
2. 初回のみ表示されるQRを1PasswordのCRMログイン項目の「ワンタイムパスワード」へ保存。QRが読めない場合は同画面のキーを登録する。
3. 保存後、1Passwordの6桁コードで登録を確定する。次回からはID・パスワードとOTPでログインする。

初回登録の手順: https://support.1password.com/one-time-passwords/

QR・キーは本人の初回登録画面でのみ表示する。確認済みのキーの再表示画面・APIはない。登録中の認証は5分・最大5回、ログイン期限は固定8時間。コード再利用はDBの原子的更新で拒否する。複数インスタンス共通の試行回数制限があり、DBや設定の障害時は認証しない。IDとパスワードを知る人は初回登録できるため、導入前にアカウントの所有者・有効状態を確認する。

## プレビューと本番

`005_user_mfa.sql` は追加テーブルと追加カラムのみ。旧版の本番ログインは変更しない。OTP・チャレンジ・セッションはlocal / preview / productionで分離。プレビューでの登録を本番へ流用しない。

各環境に別の `MFA_ENCRYPTION_KEY`（暗号学的乱数32バイトをbase64化）を設定してからデプロイする。値をGit・ログ・チャットへ出さず、VercelのSensitive環境変数で保持する。未設定・不正な鍵は認証を停止する。DBの秘密鍵はAES-256-GCMで暗号化し、ユーザーID・環境を追加認証データとして結び付ける。

新しい版では旧パスワード単独セッションを受け付けない。ログインし直して登録する。本番は別途承認を得て鍵を準備し、初回登録の案内後に切り替える。請求メールの実送信・実宛先の制限はそのまま。

## 紛失・復旧

1Passwordで復旧できない場合、管理者が本人確認したうえで、DBにアクセスできる運用端末から `pnpm exec tsx scripts/auth/reset-mfa.ts <環境> <ログインID>` を実行して対象確認する。`--apply` を追加すると対象環境のOTPを削除し、既存のMFAセッションを失効、監査記録を残す。次回はパスワード確認後に再登録する。通常画面からの無認証リセットやパスワードだけの迂回ログインは提供しない。

暗号鍵の紛失時は全OTPの再登録が必要。鍵を単純に上書きすると登録済みユーザーがログインできなくなるため、保管・ローテーションは計画して行う。パスワードとOTPを同じ1Password保管庫に保存する運用では、保管庫を奪われた場合に両方が影響を受ける。OTPはフィッシング耐性を保証する方式ではない。

## 検証

`pnpm test:auth`: RFCベクトル、許容時間窓、改ざん・鍵違い・ユーザー違い、再利用と並列実行、期限・試行上限・停止ユーザー、再登録、DBレート制限。

`pnpm test:auth:browser`: localhost限定の一時ダミーユーザーで、パスワードだけでは保護データを取得できないこと、初回登録、OTPログイン、再利用拒否、旧セッション拒否と復旧後の失効を確認する。実ユーザーのOTPを操作しない。

承認済みプレビューを検証する場合のみ、`--preview .local-test/preview-auth-test.json` を明示する。JSONはVercelでPreviewと確認したデプロイの `url`、同一ホストの一時アクセスURL `accessUrl`、対応する暗号鍵ファイル `keyPath` を含む。この設定はGitに入れない。テストはCRMプロジェクトのデプロイURLだけを受け付け、一時ダミーユーザーを終了時に削除する。
