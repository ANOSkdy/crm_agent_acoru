# 業務連絡メールの本番運用

本番画面：<https://crm-agent-acoru-acrou-pro.vercel.app/bulk-mail>

管理者が通常のOTP認証でログインし、顧客の代表メールへ手動で送信する。代表メールは請求用・担当者メールと別に管理する。仮認証キーは本番では利用できない。

## 手動送信

1. 「代表メール設定」で各顧客の業務連絡用メールを登録する。
2. 「作成・確認」で契約済み顧客を選択し、件名・本文を保存する。会社名の差し込みと固定署名に対応する。
3. 「本文・署名を確認」を押し、差し込み後の文面を確認する。この操作では送信しない。
4. 「宛先・本文を最終確認」で送信元・宛先・除外理由・本文を確認する。
5. 確認チェックを入れて「○件に今すぐ送信」を押す。この操作後にだけ、メールサービスへ送信要求を送る。
6. 「下書き・送信履歴」で各宛先の結果を確認する。「メール受付済み」はサービスの受付結果であり、到達の保証ではない。

宛先未登録・契約対象外・送信停止・同一アドレスの重複は除外する。送信開始時に宛先と本文を確定し、各通の直前にも顧客情報を再確認する。送信元変更も最終確認をやり直す対象となる。

実メールの単独テストは「実メールのテスト」タブから行う。テスト宛先はサーバー設定で固定し、準備→内容確認→チェック→1通送信の手順で実行する。顧客・代表メールの登録は不要。

## 中断と二重送信の防止

開始・継続のPOSTだけが送信処理を呼び出す。ページ表示・GET・デプロイ・起動・Cronからの業務連絡メール送信は行わない。既存の請求Cronとは独立する。

画面を閉じても、開始済みの処理は実行時間内で継続する。1回の実行は約230秒を上限とし、未送信分が残った場合は履歴の「未送信分の送信を継続」から手動で再開する。画面による自動ポーリングは状態取得だけを行う。

送信開始を永続保存してからResendへ要求する。宛先ごとの一意な配信IDと冪等キー、キャンペーン単位の排他制御で二重処理を防ぐ。メールサービス受付済み・結果確認待ちの宛先は再送しない。通信中断やレスポンス不明では送信を停止し、Resendの履歴との照合を必要とする。

処理中のサーバーが終了した場合も、その配信を未送信へ戻さない。排他期限後に手動で継続すると、十分に時間が経過した中断配信は結果確認待ちとして扱い、他の未送信分だけを進める。

## 保存と設定

既存のNeon接続を使用し、`mail_campaigns`、`mail_deliveries`、`mail_customer_addresses`、`mail_stops`、`mail_events`、`mail_manual_tests` の6テーブルへ保存する。既存の顧客・請求・認証テーブルは変更しない。ローカル用PGlite、模擬送信、下書きを本番の送信キューへ自動移行しない。

本番環境変数：

- `BULK_MAIL_ENABLED=true`：本番機能の有効化。
- `BULK_MAIL_LIVE_SEND_ENABLED=true`：手動の一斉実送信を有効化。
- `BULK_MAIL_FROM`：業務連絡の送信元メール。
- `BULK_MAIL_ORIGIN`：操作を許可する本番のHTTPS origin。
- `BULK_MAIL_TEST_ENABLED=true`、`BULK_MAIL_TEST_TO`、`BULK_MAIL_TEST_FROM`：単独の手動テスト設定。
- 送信キーは既存の `RESEND_API_KEY` を使用する。テスト専用キーが設定されていれば、単独テストのみ `BULK_MAIL_TEST_API_KEY` を優先する。秘密値をローカルへコピーせず、ブラウザーにも返さない。

既存の `BILLING_*` 設定は変更しない。業務連絡を停止する場合は `BULK_MAIL_LIVE_SEND_ENABLED=false` にして再デプロイする。履歴は削除しない。
