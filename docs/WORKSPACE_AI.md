# Acoru AI — CRMを横断するアシスタント

2026-09-20。案件内チャットを独立した `/assistant` 画面へ変更。AI接続は引き続きDeepSeekを使用する。

## 使い方

`pnpm dev` で起動し、`http://localhost:3000/assistant` を開く。CRMの「AIアシスタント」からも移動できる。

- 会話履歴、新しいチャット、会話本文の検索、会話名の変更。
- 会話ごとのURL `/assistant/<thread-id>`。再読込・別の会話への移動後も保存した内容を確認できる。
- 顧客、案件、担当者、活動、タスク、採用方針、ファイルの登録情報を横断参照。
- 見出し・箇条書き・比較表と、実際に取得した記録への参照リンク。
- 進捗・方針・商談情報・活動・タスクの更新案。対象案件名と変更内容を確認し、編集してから反映する。
- モバイルでは会話履歴をメニューで開閉する。Enterで送信、Shift+Enterで改行。日本語変換中のEnterでは送信しない。

新しい会話は作成者本人の履歴。以前の案件共有会話は「旧・共有」と表示し、閲覧専用で残す。CRMに反映した進捗やタスクは従来通り社内共有。案件詳細には現在の進捗・方針と「AIに相談する」を表示する。

## 回答の根拠

`crm_ai_records` は業務情報だけを投影するビュー。削除済みの顧客・案件とその子レコード、認証情報、個人会話は検索対象に含めない。値はSQLパラメーターとして渡し、モデルには任意SQLを実行させない。

| ツール | 用途 |
| --- | --- |
| `search_crm` | キーワード・種類・顧客・案件・状態・日付による検索。20件ずつ、全一致件数と続きの有無を返す |
| `get_record` | 記録本文。案件は最新の進捗・活動・タスクと更新判定用の版も取得 |
| `get_crm_metrics` | 件数・金額・確度加重金額・ステージ別・期限超過をSQLで集計 |
| `get_priority_items` | 期限超過、14日間活動記録なし、30日以内の受注予定、要注意・停滞を抽出 |
| `search_conversation` | 同じ会話の過去の発言を検索 |
| `finish_response` | 本文・取得済み参照元・対象案件付き更新案を検証して保存 |

モデルの検索だけで全件の金額を推測しない。集計はDBで計算し、日付の意味と対象範囲を返す。期限は日本時間を基準に判定する。活動の未記録と実際の停滞を区別する。取得していない参照元IDや本文と不一致の出典は受け付けない。

標準では直近40メッセージをモデルに渡す。案件詳細の関連情報は活動30件・タスク100件・方針20件まで。追加情報は検索をページ送りして取得できる。長い本文は1項目5,000文字まで。登録されたファイルの本文・外部Webページ・メールボックスは参照しない。

最大8回のモデル応答、各応答60秒・全体140秒。終盤は取得済みの情報で回答を確定する。検索結果が足りない場合は、その限界を回答に明示させる。回答の正確さを無条件に保証するものではなく、参照記録から確認できる設計にする。

## 保存と権限

`003_workspace_assistant.sql` を適用済み。既存テーブルのデータを保持し、`agent_threads.deal_id` を任意にしてタイトル・更新日時を追加。`agent_runs` に実行中の表示とツール履歴を追加した。モデル・トークン使用量・実行結果を保存する。

APIはログイン、同一オリジン、入力スキーマ、会話の所有者を検証。案件の更新権限は管理者または担当者。viewerは参照のみ。新しい個人会話の更新案は旧案件APIからも取得できない。更新の競合検出・原子的な反映・二重反映防止は既存のDB関数を使用する。

会話と利用者の発言を先に保存してから生成する。ブラウザーには実際の検索状況を通知し、完成した回答は保存後に表示する。ページを開き直した場合は保存済み状態を取得する。中断した処理を自動再実行するワーカーはなく、3分以上残った処理は失敗として再送を案内する。利用上限は利用者あたり1時間30回。

## 検証

```text
pnpm typecheck
pnpm lint
pnpm test:agent
pnpm test:agent:db
pnpm build
```

実データを書き換えず検証する場合は `pnpm exec tsx scripts/test-fixture.ts workspace` で2社の一時データを作り、以下を使う。

```text
node --conditions=react-server --import tsx scripts/test-assistant-data.ts
pnpm exec tsx scripts/test-assistant-api.ts read
pnpm exec tsx scripts/test-assistant-api.ts before
pnpm exec tsx scripts/test-assistant-api.ts after
pnpm exec tsx scripts/test-fixture.ts cleanup
```

API検証は、ブラウザーで比較相談→更新案作成→内容編集・反映という順に進め、各段階で実行する。検証用セッションが期限切れなら `scripts/test-fixture.ts renew` でそのセッションだけ延長できる。

ローカルのアプリ・接続先DBを更新。本番アプリのデプロイは別途必要。
