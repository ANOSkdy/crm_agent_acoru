# 課題管理

顧客別タブで課題を管理します。登録済みの顧客であれば契約・請求の有無やアクティブ状態を問わず追加できます（削除済み顧客を除く）。タブはDBに保存され、課題が0件でも残ります。

列は No、起票日、内容、完了条件、期限、進捗、状態の順です。Noは顧客内で一意の正の整数です。追加時は空欄で自動採番、指定もできます。Noリンクから全項目を編集し、一覧の状態は直接変更できます。状態は未着手・対応中・完了・不要です。完了と不要は期限超過件数に含めません。日付表示と本日の判定は日本時間です。

## DB移行

アプリの切り替え前に、対象環境の DATABASE_URL を設定して以下を実行します。

```sh
npm run db:migrate
```

013_issue_management.sql が新規フィールド、顧客タブ、顧客別採番、制約を追加します。既存のタイトルは内容、説明は進捗、作成日時の日本時間の日付は起票日に引き継ぎます。既存の open/done は未着手/完了です。顧客未設定の既存データは専用タブで確認し、編集で顧客を設定できます。

既存マイグレーションは適用済みチェックサムとの互換性のため変更しません。廃止機能の過去データを含むテーブルも保存します。RAWの課題・意思決定・工数反映は独立した処理に変更しています。移行013は、PRマージ前の稼働アプリとの互換性のため旧AI更新関数と検索ビューを残します。新しいアプリのデプロイ後、scripts/db/post-deploy/retire_legacy_features.sql を適用すると旧DBオブジェクトも削除できます。既存の活動・ファイル等のデータテーブルは保存されます。

## DB適用記録

2026-10-29、設定済みDBへ移行013を適用しました。課題の業務データ、顧客・活動・ファイルの件数が保持され、新項目・顧客タブが作成されたことを確認済みです。既存DBの更新トリガーにより課題の更新日時は移行時点に更新されます。旧画面向けビューと旧AI更新関数の削除はアプリ切り替え後に実施します。

同日、Vercel Previewの接続先がローカル設定・Productionとは別のDBで、移行012・013が未適用だったことを確認しました。Preview DBを個別にバックアップして両移行を適用し、既存の課題・顧客等の保持を確認しました。環境ごとの接続先へ移行を適用する必要があります。

Vercelのビルド開始時には `scripts/db/check-schema.mts` が、そのデプロイの `DATABASE_URL` に対して移行履歴・チェックサム・課題管理の列とタブを読み取り確認します。移行漏れや不整合がある場合はデプロイ前に失敗させます。この確認処理はDBを更新しません。

## 廃止機能

AIアシスタント、活動履歴、ファイル管理、レポートの画面・API・専用実装を削除しました。顧客サマリー生成と案件AI相談も対象です。RAW受信箱と工数はそれぞれ /raw、/work-logs で利用でき、アシスタントへのリダイレクトはありません。活動履歴を新規作成するRAW候補は受け付けません。
